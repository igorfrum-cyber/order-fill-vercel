# Документация проекта Order Fill

Этот каталог фиксирует целевое состояние продукта и план переписывания текущей frontend-only автоматизации в промышленный сервис для расчета и подготовки заказов.

## Документы

- [Архитектура](./ARCHITECTURE.md) - целевая сервисная архитектура, границы сервисов, потоки данных и инфраструктурные решения.
- [Техническое задание](./TECHNICAL_SPEC.md) - продуктовые, функциональные и нефункциональные требования.
- [План переписывания](./plans/2026-08-27-service-rewrite.md) - пошаговый план миграции текущего кода в новую сервисную архитектуру.

## Текущий контекст

Существующая версия работает полностью в браузере: пользователь вручную загружает Excel-файлы, JavaScript-код читает и изменяет `.xlsx`, показывает отчет и отдает файлы на скачивание. Это подходит для внутренней автоматизации, но плохо масштабируется как продаваемый продукт:

- бизнес-логика смешана с UI;
- обработка документов зависит от браузера пользователя;
- нет очереди задач и истории обработок;
- нет централизованного хранения файлов и аудита;
- сложно добавить роли, интеграции с 1С, фоновые расчеты и параллельную обработку.

Целевое направление: сервисная система, где frontend остается тонким клиентом, Go-сервисы отвечают за API, jobs и обработку Excel, а Python добавляется позже как отдельный расчетный/ML-сервис.
