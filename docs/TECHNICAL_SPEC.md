# Техническое задание

## Назначение продукта

Система автоматизирует подготовку заказов по брендам на основе Excel-таблиц из 1С и актуальных бланков поставщиков. Пользователь должен тратить время только на проверку спорных строк, а не на ручное копирование, сверку и расчет количества.

## Целевая аудитория

- закупщики;
- руководители закупок;
- менеджеры городов/складов;
- операторы, которые готовят заказы для поставщиков;
- администраторы продукта.

## MVP

На первом этапе система работает с Excel-файлами:

- таблица заказа товара из 1С;
- актуальный бланк поставщика;
- для CHRISTINA два бланка: HOME и PROFF;
- для режима "Север" несколько заполненных бланков городов;
- опционально заполненная таблица Тюмени для учета остатков.

Интеграция с 1С, пользователи, роли и ML-расчеты не входят в первый этап, но архитектура должна их поддерживать.

## Поддерживаемые бренды

- ANGIOPHARM;
- CHRISTINA;
- LeviSsime;
- SOTHYS;
- NOVACUTAN;
- Skin Synergy;
- KLAPP.

## Основной сценарий: заполнение бланка

Пользователь выбирает бренд и месяц заказа, загружает таблицу заказа из 1С и актуальный бланк. Система создает задачу обработки, проверяет файлы, рассчитывает количества, заполняет бланк и показывает отчет.

Система должна:

- проверить, что период в таблице заказа соответствует выбранному месяцу;
- найти нужные колонки по заголовкам, а не по фиксированным буквам;
- нормализовать артикулы;
- сопоставить позиции источника и бланка;
- округлить рекомендации по правилам бренда;
- очистить ячейку заказа, если рекомендация меньше минимального порога;
- показать спорные строки;
- дать пользователю изменить количество;
- потребовать комментарий при ручном отклонении от расчетного значения;
- записать ручные отклонения в таблицу заказа в колонки "Заказано по факту" и "Комментарий";
- сформировать итоговый бланк и заполненную таблицу заказа.

## Сценарий: отчет по спорным строкам

Система должна показывать отдельный блок "Нужно проверить".

В него попадают:

- совпадение только по названию;
- артикул найден, но название сильно отличается;
- позиция есть в бланке, но ее нет в таблице заказа;
- позиция есть в таблице заказа, но ее нет в бланке;
- дубли артикулов в источнике;
- дубли артикулов в бланке.

Пользователь должен иметь возможность скачать CSV-отчет для исправления данных в 1С.

## Сценарий: Север

Пользователь загружает заполненные бланки городов. Система объединяет потребности и строит общий план.

Система должна:

- определить город по названию файла, листа или параметрам внутри файла;
- не принимать несколько одинаковых бланков одного города и типа;
- поддерживать Сургут, Нижневартовск/Вартовск, Уренгой, Тюмень;
- учитывать отдельные HOME/PROFF бланки для CHRISTINA;
- собрать потребность по каждому товару;
- при наличии таблицы Тюмени учесть остаток, товар в пути и целевой запас;
- определить, что можно закрыть перемещением из Тюмени;
- определить, что нужно заказать у поставщика;
- дать пользователю изменить городские количества и факт заказа у поставщика;
- предупредить, если факт заказа меньше потребности;
- сформировать общий бланк;
- сформировать файлы перемещения;
- для NOVACUTAN сформировать таблицу заказа.

## Правила брендов

### ANGIOPHARM

- Округление до целой коробки.
- Если увеличение до коробки не больше 15%, округлять вверх.
- Если уменьшение до коробки не больше 5%, округлять вниз.
- Автокомментарий: `до коробки`.

### CHRISTINA

- Два бланка: HOME и PROFF.
- Округление до кратности 3.
- Автокомментарий: `до кратности 3`.

### LeviSsime

- Поддержка артикулов с префиксом `MT`.
- Колонка заказа определяется как `Заказ`.
- Размер упаковки определяется по колонке количества в упаковке.

### SOTHYS

- Поддержка бланков с двумя товарными блоками на одном листе.
- Артикулы с дефисами должны сохраняться.
- Округление только до целого, без коробочного правила.

### NOVACUTAN

- Сопоставление преимущественно по названию.
- Поддержка минимальных партий.
- Для отдельных товаров применяются минимумы 10, 50 или 100.
- Для масок возможна поставка коробками по 5 штук.

### Skin Synergy

- Поддержка бланков без обязательной колонки объема.
- Колонка заказа определяется как точная колонка "Количество".

### KLAPP

- Заказ округляется до ближайшей кратности 3.
- Автокомментарий: `до кратности 3`.

## Нефункциональные требования

### Контейнеризация

- Все сервисы должны запускаться через Docker.
- Локальная разработка должна подниматься одной командой через Docker Compose.
- Каждый собственный сервис должен иметь отдельный `Dockerfile`.
- Compose-стенд должен включать frontend, api-service, document-service, PostgreSQL, queue и object storage.
- Сервис считается готовым к интеграции только при наличии контейнерного запуска и healthcheck.
- Production-сборка не должна зависеть от локально установленных runtime на машине разработчика.

### Производительность

- Задача обработки одного комплекта файлов должна выполняться в фоне.
- API не должен блокироваться на время обработки Excel.
- Система должна поддерживать параллельную обработку нескольких jobs.
- Время обработки должно измеряться и сохраняться в job metadata.

### Надежность

- Исходные файлы не должны теряться после загрузки.
- Ошибка обработки не должна приводить к потере исходных данных.
- Worker должен поддерживать retry для временных ошибок.
- Все ошибки должны сохраняться в истории job.

### Безопасность

- Файлы должны быть доступны только владельцу задачи или пользователям организации.
- Нужно ограничить размер файлов.
- Нужно проверять расширение и реальный формат файла.
- Нельзя выполнять макросы из `.xlsm`.
- Нужно логировать скачивание и финализацию.

### Наблюдаемость

- Каждый job получает `job_id`.
- Логи сервисов должны включать `job_id`.
- Должны быть метрики: количество jobs, ошибки, длительность обработки, размер файлов.

## Форматы результата

Для обычного заполнения:

- заполненный бланк;
- заполненная таблица заказа;
- CSV-отчет спорных строк;
- JSON-отчет для UI.

Для "Севера":

- общий бланк;
- файлы перемещения по городам;
- таблица заказа, если нужна для бренда;
- JSON-план распределения.

## Что не входит в первый этап

- автоматический обмен с 1С;
- роли и права;
- платежи и тарифы;
- ML-прогнозирование;
- мультиорганизационность;
- мобильное приложение;
- редактирование справочников брендов через UI.
