# Изменение проекта

Статус: действующий. Область: разработка. Проверено: 14 октября 2026 года.

Начать с [карты модулей](../architecture/modules.md) и [продуктовых правил](../README.md). Проверить ветку и чужие рабочие изменения. В фасады логику не возвращать.

Бренд: обновить `domain/brands/rules.js`, quantity/budget rules, при необходимости Excel blanks. Добавить синтетический workbook и проверку количества, комментария, цены и экспортируемого файла. Обновить продуктовый документ.

Формула: изменить одного владельца domain и проверить пустое значение, ноль и округление. Адаптер применяет формулу и не содержит второй копии. Изменение поведения требует отдельного решения; baseline внутреннего переноса остаётся неизменным.

UI: соответствующие controller/events; bootstrap отвечает за сборку и порядок. Проверить shared state, generation/revision и object URL, ввод/ошибки/отмену/скачивание. Screenshot не заменяет взаимодействие.

Excel: существующие XML-примитивы, сохранность ZIP-частей, формул, стилей, связей, расширения и макрос-сегментов. Неопределённый остаток не превращать в ноль.

Перед review выполнить [полный gate](testing.md), проверить diff и индекс. Новое архитектурное решение записать в decisions; завершённый план маркировать завершённым.

## Что хранить в Git

В Git остаются код, конфигурация сборки без секретов, lock-файл, документация, генераторы синтетических fixtures и канонический JSON baseline расчётов. Служебные PNG/DOM-снимки, результаты скачиваний, бинарные Excel-примеры, пользовательские книги, отчёты тестов, кэши и локальные настройки исключены .gitignore. Нужные картинки/иконки интерфейса в src/ и public/ сохраняются; глобального запрета на PNG/SVG нет.

Секреты хранить только локально в .env или отдельном secrets/. В .env.example, .env.*.example и .env.template допускаются только пустые значения/образцы. Не помещать ключи внутрь отслеживаемых JS/JSON/Markdown: .gitignore проверяет путь файла, а не его содержимое. Дополнительный gate проверяет известные сигнатуры ключей и случайно отслеживаемые игнорируемые файлы.

Если нужен настоящий workbook-шаблон как ресурс приложения, сначала добавить явное исключение конкретного пути, проверить содержимое и документировать назначение. Уже закоммиченные артефакты исключать через git rm --cached с сохранением локальной копии; история Git этим не переписывается. Для случайно опубликованного реального ключа потребуется его отзыв/замена отдельно от настройки .gitignore.
