# Обзор платформы и иерархия компании

## Цель

Администратор сервиса сразу видит, жива ли система и кто менял доступ. Владелец и администратор компании видят, кто есть кто, и когда человек последний раз входил.

## Обзор (только platform_admin)

Домашний экран — «Обзор», не пустые выгрузки. Пункт «Выгрузки» остаётся в меню.

Сверху пять плиток: API, обработчик бланков, база, очередь, файлы. Зелёный — отвечает, красный — нет, серый — ещё проверяем. Подпись человеческим языком, без метрик.

Ниже две колонки:

- живые выгрузки по всем компаниям (существующий `GET /api/v1/jobs`);
- лента доступа: приглашения, сброс, отключение человека или компании, смена пароля. Входы в ленту не входят.

Новый `GET /api/v1/status` только для platform_admin. Он пингует Postgres, Redis, MinIO и `DOCUMENT_HEALTH_URL` (healthz обработчика). Сам API считается живым, если запрос дошёл. `/healthz` не меняется — это liveness для Docker.

Лента берёт уже существующий `GET /api/v1/audit`, но отдаёт только действия с доступом и добавляет логин автора и имя компании.

## Иерархия компании

На «Пользователях» три уровня сверху вниз: владелец, администраторы, закупщики. Без паутины линий — только полосы и карточки.

Карточка: инициал, логин, роль, последний вход («сегодня, 14:32» / «ещё не входил»). Отключённые приглушены. Кнопки «Сброс доступа» и «Выключить» остаются у тех, кем можно управлять.

Последний вход — `MAX(at)` по `login_success` в `audit_events`, поле `last_seen_at` в списке пользователей.

Админ сервиса видит ту же схему после выбора компании.

## Границы

Не строим Grafana, не кладём логины в ленту, не меняем расчёт бланков, не даём закупщику этот экран (у него нет «Пользователей»).
