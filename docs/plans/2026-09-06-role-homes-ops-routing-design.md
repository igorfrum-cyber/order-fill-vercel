# Дома по ролям, ops-контур и URL

Дата: 2026-09-06  
Статус: согласовано. Север не трогаем, пока этот сценарий не допилен. Остальное доводим, чтобы продукт не ощущался сырым, роли были правильными, а новые экраны добавлялись в одно место.

Связанные документы:

- роли и обзор: `docs/plans/2026-09-02-ops-overview-design.md`
- микросервисы: `docs/plans/2026-09-04-microservice-architecture-v2-design.md`
- закупщик → загрузка: `docs/plans/2026-09-05-purchaser-upload-preview-downloads.md`

## Зачем

Один UI на все роли, пункты меню просто прячутся. Экран живёт в `useState`, в адресе только `/invite/:token` и `/c/:slug`. После обновления страницы человек теряет место. Обзор знает пять старых зависимостей, а не сервисы v2. Графиков нет.

Нужны: свой дом у роли, человеческий Обзор и отдельная страница метрик в этом же приложении, URL как источник экрана.

## Роли и дома

| Роль | Дом | Меню | Главная работа |
|---|---|---|---|
| `purchaser` | загрузка бланка | Работа, Файлы, профиль | положить файлы, проверить строки, скачать |
| `company_admin` | пульс компании | Очередь, Люди, Компания, Файлы | пригласить закупщика, застрявшие выгрузки, профиль компании |
| `company_owner` | пульс компании | то же | то же плюс пригласить админа; правит данные компании |
| `platform_admin` | Обзор | Обзор, Метрики, Компании, Люди, Выгрузки | здоровье контура, графики сервисов, завести компанию и владельца; выгрузки не создаёт |

Владелец и админ компании оба редактируют название, логотип и адрес входа. Пункт «Компания» не прячем. Режим сопоставления (`standard` / `smart`) по-прежнему только у `platform_admin`.

Закупщик: дом — загрузка бланка закупки. Недоделанная выгрузка «На проверке» важнее новой. Баннер passkey — после первой успешной выгрузки или в профиле, не поверх dropzone.

Север оставляем как есть: текущая кнопка и `NorthApp` без правок, без слияния с бланком, без UX-полировки этого потока.

Админ сервиса: переключатель компании один, в шапке, на все экраны. После создания компании сразу «Пригласить владельца». CTA «заполнить бланк» на его Выгрузках нет.

Справка режется по роли. Строки истории открываются ссылкой, не только кликом по `<tr>`.

## Обзор и страница метрик

Оба экрана живут в этом приложении, оба только для `platform_admin`. Grafana и чужой UI не используем.

**Обзор** (`/overview`) — человеческий. Плитки health/readiness, без графиков.

Не 14 одинаковых тайлов. Три группы с одним светофором, внутри — кто молчит:

- **Вход:** gateway, identity, twofa, passkey
- **Выгрузки:** job, document, matching, brand, calculation, file
- **Инфра:** Postgres, Redis, MinIO, audit

Заголовок: «Все сервисы отвечают» или «Сопоставление не отвечает». Красный в группе выгрузок ведёт к живым джобам.

**Метрики** (`/metrics`) — техническая страница в том же фронте: RPS, ошибки, latency HTTP/gRPC по сервисам, лаг очереди, длительность джоба, runtime. Пункт меню «Метрики», не ссылка наружу.

Данные тоже из нашего сервиса: браузер ходит только на gateway. `GET /api/v1/metrics/query` (и при необходимости range) — только `platform_admin`, фиксированный набор рядов, не свободный PromQL из браузера.

Prometheus в compose — внутреннее хранилище рядов. Скрейпит `/metrics` сервисов по внутренней сети, порты на `127.0.0.1`. Пользователь Prometheus не открывает. Gateway запрашивает у него готовые ряды и отдаёт JSON фронту.

`GET /metrics` на самих сервисах снаружи сессии не отдаём. Старый JSON-снимок в `backend/pkg/metrics` для v2 заменяется Prometheus-форматом.

Это снимает «не строим Grafana» из обзора 2026-09-02: графики есть, но как страница продукта, не как отдельный продукт.

## URL

Сейчас после входа экран не в адресе. Nginx уже делает `try_files … /index.html` — новые пути фронта шлюз не обслуживает. Отдельные HTTP-роуты на gateway под SPA не нужны.

Целевые пути:

| Путь | Кто | Что |
|---|---|---|
| `/invite/:token` | гости | как сейчас |
| `/c/:slug` и поддомен | гости | вход компании, как сейчас |
| `/` | сессия | редирект на дом роли |
| `/overview` | platform_admin | Обзор |
| `/metrics` | platform_admin | графики сервисов |
| `/jobs` | все | история |
| `/jobs/new` | не platform_admin | бланк закупки, стадия загрузки |
| `/jobs/:id` | кто видит джобу | продолжить по статусу |
| `/companies` | platform_admin | список компаний |
| `/company` | owner, company_admin | профиль компании |
| `/users` | не purchaser | люди |
| `/account` | все | профиль |

Выбранная компания у platform_admin — query `?company=`, чтобы пережить обновление. Чужой для роли путь → редирект на дом, не пустой экран. Неизвестный путь → простая 404 в SPA.

`GET /api/v1/jobs/{id}` уже есть: `/jobs/:id` на фронте только читает id из URL. Новых job API из-за роутинга не делаем.

Библиотеку роутера не требуется заранее. URL — источник правды, `history` API достаточно.

Навигация и дома ролей живут в одной таблице (`navForRole` / разбор pathname). Новый экран продукта — новая строка, не ветвление в `App.jsx`. Путь Севера, если понадобится позже, тоже добавляется туда, не размазывается по компонентам.

## Чтобы не ощущалось сырым (бланк закупки и админка)

Не трогая Север:

- история: ссылка на строку, скачать готовое из списка, фильтр бренд/статус/месяц, poll как на Обзоре;
- проверка строк: очередь «дубли → проверить → скачать», не набор равноправных вкладок;
- шаблоны комментария в гейте: «округление», «нет на складе», «поставщик»;
- после выбора таблицы 1С — подсказка бренда по имени файла (уже есть `looksLikeChristinaSource`);
- инвайт: у человека «ещё не входил» кнопка «скопировать ссылку снова» через уже существующий сброс доступа;
- справка только про роль; passkey-баннер не на первом шаге закупщика;
- скелет вместо голого «Загрузка…»; подписи у полей, не один placeholder;
- превью Excel на узком экране: «откройте на компьютере»;
- у platform_admin компания в шапке, не отдельный select на каждой странице;
- за 10 минут до конца сессии предупреждение (для этого `/me` отдаёт `session_expires_at`).

Повтор упавшей джобы, смена файлов местами, SMTP, тёмная тема, сравнение с прошлым месяцем — не в этом заходе.

Страница `/metrics` и расширенный `GET /api/v1/status` — после того как сервисы отдают Prometheus `/metrics`. Пока пункта «Метрики» в меню нет: пустая страница сырее, чем его отсутствие.

## Что готовит бэкенд параллельно

Маленькое, чтобы фронт сессии не врал:

- `session_expires_at` в `GET /api/v1/auth/me`.

Ops, когда сервисы уже с Prometheus:

- health/readiness у каждого сервиса v2; `GET /api/v1/status` расширить до групп выше, не ломая `{ components: [{ id, ok }] }`;
- `/metrics` Prometheus-формата у каждого сервиса, только внутренняя сеть;
- Prometheus в compose как TSDB;
- `GET /api/v1/metrics/query` на gateway для страницы `/metrics`.

Поведение джоб, прав и инвайтов не менять ради URL.

## Что фронт делает в этом заходе

Дома по ролям, pathname, история без сырости, очередь проверки бланка, инвайт «скопировать снова», справка по роли, passkey не на первом шаге закупщика, скелеты, компания в шапке у platform_admin.

Северный UI не менять. Страницу метрик не рисовать, пока нет query API.

## Не делаем в этом заходе

- любые правки Север-потока (`NorthApp`, north workflow, north copy/tour);
- Grafana как UI;
- свободный PromQL из браузера;
- пустой пункт «Метрики» до API;
- новые роли и RBAC;
- SMTP инвайтов;
- отдельные backend-роуты вида `/jobs/:id` вне `/api/v1`.
