# Пересчёт таблицы

Раздел принимает таблицу бренда без бланка поставщика. Обязательны бренд и месяц заказа. Опционально загружается второй склад Тюмени.

Обработка: копия исходника → объединение двух складов (если выбрано) → общая процедура чтения и объединения ЧЗ → пересчёт категорий и месячной потребности → целевой запас с доставкой → рекомендация с учётом остатков и товара в пути.

`recalculateOrderTable` в `src/workbookProcessor.js` использует существующий `readSource`, без отдельной формулы прогноза. Рекомендация остаётся расчётной: кратность и минимальная партия поставщика применяются при заполнении заказа, не подменяют рекомендацию таблицы.

При одиночном пересчёте фактический заказ и комментарии не стираются. При объединении `preserveFacts: true` суммирует непустые фактические количества подтверждённых одинаковых позиций, включая явные нули; разные комментарии сохраняются через точку с запятой. Обычный сценарий объединения без этого флага не изменён.

Неоднозначные строки сохраняются отдельно и выводятся списком для проверки. Исходные файлы не меняются. Результат скачивается отдельным файлом. Периоды и сроки поставки проверяются общей процедурой.

Интерфейс: `src/recalculateTable.js`. Во время обработки поля блокируются, при смене входных данных старая ссылка на результат удаляется. Проверки сохранности факта и комментариев для одной/двух таблиц: `scripts/test-tyumen.mjs`.
